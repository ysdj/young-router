# Young Router Repository Guide

## Scope

- Treat `young-router` as a standalone repository. Do not inspect parent directories for repository instructions.
- Keep provider names, models, API keys, request IDs, local paths, traces, and logs out of committed files. Public examples use only neutral synthetic values.
- `config.example.yaml` is the public configuration example and must remain safe to publish.

## Source Of Truth

- `rn/packages/shared/` owns shared React/TypeScript routes, composition, interaction state, i18n, and the typed Core IPC client.
- `young_router/core/` owns domain state, validation, staged configuration, service operations, persistence, and the authenticated versioned loopback IPC contract.
- `rn/apps/macos/` is the AppKit host and `rn/apps/windows/` is the WinUI 3 host. Native code owns platform leaves: status/tray menus, windows, native controls, system WebView hosts for shared code panes, secure inputs, file panels, alerts, shortcuts, and platform lifecycle.
- One feature has one shared UI and one Core domain implementation. Do not introduce a second platform-specific domain store, configuration writer, WebView application shell, Electron/Tauri layer, or legacy shell launcher. Embedded system WebViews are permitted only for the shared code panes.
- React holds view state only. It must not write configuration files, manage the proxy process, read arbitrary paths, or handle raw credentials. Versioned code-editor document text is the explicit exception.
- The language choice belongs in each host's native application menu. Shared UI consumes that preference; do not add an in-window language selector.
- All user-visible shared strings go through i18n. Keep platform titles and menu labels aligned with the selected language.

## UI And Native Boundaries

- Preserve native platform behavior and visual conventions. Shared UI describes the workflow; native leaves render controls that require AppKit or WinUI behavior.
- Default every desktop surface to compact native density. Avoid redundant in-content titles, oversized empty cards, web-like vertical whitespace, and detached action rows; prefer tightly grouped 24–28 px controls, concise helper text, content-sized route windows, and one fixed bottom action bar. Tabs must be genuinely switchable and render only their active pane. Compact layouts must still reflow before controls overlap or hide required content on either macOS or Windows.
- A route window's bottom-right action bar contains only `Close` and a conditional `Apply` when staged configuration is dirty. File selection, import/export, WebDAV testing, and synchronization actions belong in the active pane, never in that footer.
- Every subordinate surface presents itself through one child-window contract: the provider wizard, the raw file editor, 分组管理, the relay sign-in browser, the relay usage log, the read-only document viewer, the official provider sign-in, and the model chooser each open their own movable titled window above the window they were opened from, with that window's content locked until the surface closes. The lock is `NativeChildPanelShield` — a view over the parent's content that swallows every mouse event and holds the first responder, plus the parent's disabled window buttons — and never a modal session or an attached sheet: `NSApp.runModal` freezes the React host — see the child-surface modal freeze incident — and an AppKit sheet cannot be dragged and draws no title bar. The child opens through `presentChildPanel(_:in:prepare:)`. Every dismissal path — the title-bar close button, an in-surface Close or Apply, and a resolved completion — ends the child through `endChildPanel`, which releases the lock, detaches the child window, and ends the children that child opened; a warm window is only created (`warmOnly:`) and never presented, so a surface that is not on screen never holds a lock.
- A settings pane that splits its body into a list plus a detail renders the shared `SettingsRail` (runtime settings, backup & sync, external clients): one width, one source-list column, one row rhythm — not a per-pane list of its own. The rail is the sidebar's *compact* source list, so it shares the sidebar's chrome, type step, and ink while stepping one density down (sidebar 30 pt row + 2 pt spacing = 32 pt pitch, rail 26 + 2 = 28 pt pitch, the platform's own in-pane row height). A symbol-less source-list row keeps that type step and ink (`SourceListFont()`/`SourceListTitleColor` on macOS, `kSourceListFontSize` at medium weight on Windows) instead of the 13 pt regular body cell, and the host swaps the ink by hand on the emphasized selection.
- Every settings-pane window keeps one permanently mounted bottom status strip, rendered one type step below body text (`UI_TIP_FONT_SIZE`). A pane result replaces the localized idle `common.ready` (就绪) label; never mount that strip conditionally on a result, because the pane must not shift or resize whenever an action reports.
- Use typed IPC snapshots and actions. Never expose a path, secret, or unrestricted native capability through ordinary React props. Versioned code-editor document text may flow through the shared code-editor view.
- Every `@objc` method on `AppKitNativeLeafModule` (or any `RCT_EXTERN_MODULE` class) must also be declared in `rn/apps/macos/src/native/macos/AppKitNativeLeafBridge.m` with `RCT_EXTERN_METHOD(...)`. The TurboModule interop exposes only methods listed there; an undeclared method is `undefined` in JS and `bridge.foo?.()` optional chains silently no-op with no warning or log. Always pair a new export with an assertion in `tests/test_rn_native_acceptance.py`.
- Route windows must render their first data-backed frame from the shared snapshot; do not paint empty shells and refill them or issue duplicate per-window snapshot/subscription requests.
- Secure inputs and file panels use opaque one-time native capabilities. Do not serialize secret values into IPC snapshots, logs, drafts, or test fixtures. Raw configuration documents use the authenticated versioned editor IPC instead of the retired native-only editor path.
- Keep configuration changes staged and explicit. Validation may update draft state, but writing configuration and restarting a service require an explicit Apply action.
- A native surface reports a wait in flight with the app's own busy wheel, never a progress-indicator view: `AppKitBusySpinner` owns the frames on macOS (the Fabric busy button reads them through the generated Swift header and the 分组管理 sheet turns the same ones beside 密钥), Windows keeps its platform `ProgressRing`, and the wait's words ride the wheel as its tooltip and accessibility label. The wheel swaps pre-rendered frames instead of animating a view, so nothing re-lays out while it turns.

## Runtime And Compatibility

- The runtime starts from `.litellm-runtime/config.yaml`; source configuration is validated and staged explicitly. No file mutation may silently restart the service.
- Keep proxy data-plane headers transparent. Outside an explicitly scoped compatibility hook or runtime patch, do not add, remove, rename, rewrite, normalize, mask, or impersonate request or response headers. Preserve downstream-supplied headers byte-for-byte when forwarding them upstream, including headers or values that identify LiteLLM; do not invent upstream identity headers or strip LiteLLM/SDK fingerprints merely to conceal the implementation. Every header exception must stay narrowly tied to its documented protocol or failure mode and have a focused regression test.
- Nothing this app sends may identify it. A downstream client's `User-Agent` is forwarded byte-for-byte; a request without one, and every request the app makes on its own behalf (relay dashboard calls, provider probes, usage-log reads, WebDAV, helper workers, local proxy calls), presents the shared browser identity from `young_router/browser_identity.py` instead of an app, tool, or SDK fingerprint. The native hosts pin the same literal (`RelayBrowserIdentity` on macOS, `kRelayBrowserUserAgent` on Windows) so one account keeps one fingerprint — a relay that binds a session to its IP and `User-Agent` (sub2api's session binding) revokes the session family on any mismatch. The only exception is a loopback-only control call (Core IPC, the proxy's own health endpoint), which may keep an internal marker because it never leaves the machine. `tests/test_browser_identity.py` is the guard: it compares the Python and native literals, scans shipped request code for self-naming `User-Agent` values, drives the data-plane steps, and covers the staged-package rewrite. Never add a User-Agent, product token, or `X-...` client name that names this app, its hosts, or its helper packages; when a helper package sends one of its own, normalize it in the same staging step that adapts that package.
- Every artifact-producing desktop build must update `LITELLM_VERSION` from the latest installable stable LiteLLM release on PyPI before selecting or reusing a bundled runtime and before invoking the platform build. This applies to direct macOS and Windows builds, macOS build-and-install, and release packaging. If the update cannot complete, fail the build; never silently package a stale lock. A nested build may skip only a duplicate lookup already completed successfully by the same top-level build invocation.
- Every artifact-producing desktop build must also re-check each third-party integration against its latest upstream release and adapt the repository when upstream drifted; never package a stale adaptation. `pi-web-access` (npm, `nicobailon/pi-web-access`) is staged from the npm `latest` dist-tag by `scripts/update_pi_web_access.py` on every build, so its adaptation surface is the published Pi peer graph, the staged worker smoke test, and the User-Agent normalization `_normalize_staged_user_agents` — add a missing `@earendil-works/...` package to `FALLBACK_PI_PEERS` only when that smoke test demands it, and when upstream renames or drops the self-naming `User-Agent` literals the staging step must fail loudly and be re-checked rather than silently shipping them. `dsh-vision-router` (npm, `ysr666/dsh-vision-router`) is a Node/Cordis plugin that no build step fetches, so its mirrored subset — `young_router/dsh_vision_router.py`, the Vision Router entries in `young_router/core/runtime_settings_schema.py`, and the default fallback config JSON — must be re-checked against the current upstream release before builds: free OVH chain models and order, local Ollama/LM Studio defaults, and `freeFallback`/`timeoutMs`/`maxTokens`/`httpProviders` semantics. `TraceOne` (GitHub, `wangchao0708/TraceOne`) is staged from its default branch by `scripts/update_traceone.py` on every build and powers the model detail pane's degradation deep test through `young_router/traceone.py` and `young_router/traceone_worker.mjs`; its adaptation surface is the staged `dist/traceone.js` exports (`TARGET_MODELS`, `parseGridResponse`, `identifyWithArtifacts`), the three `dist/data` artifacts, and `prompts/identity-web-v1.txt`, which the staging script validates together with a real staged-worker smoke test — when upstream renames one of them, update the staging file list, the adapter, and the deep-test plan together. Any new third-party integration enters this list with its latest-version check and adaptation surface; LiteLLM keeps the rule above.
- The macOS LiteLLM proxy must run with `LITELLM_NUM_WORKERS=16`. Do not lower the default, alter it during a restart, or use a smaller worker count as a performance or recovery workaround unless the user explicitly requests that configuration change.
- Every newly created proxy process must start with empty route-recovery and deployment-cooldown runtime state. Never carry `.litellm-runtime/route-recovery-state.json` or `.litellm-runtime/deployment-cooldowns.json` across app starts, service starts, restarts, or reloads.
- Preserve LiteLLM routing, Responses stream semantics, tool ordering, IDs, explicit terminal errors, and metadata-driven compatibility bridges. Do not add request-specific or provider-specific routing hacks.
- The Core IPC schema beside the implementation is the durable contract. Update its validators, typed client, host bridges, and focused tests together when the contract changes.
- Core event delivery and the shared revision are per-window contracts: the host bridge fans one Core event stream out to every registered window module, and every host passes Core's private `--metadata` path (an unreadable file counts as absent state) so a replacement Core resumes the shared revision.
- The macOS Vision helper is built into `Contents/Resources/Core/bin/vision_ocr`. Keep its source in the RN macOS host and never restore a `Resources/App` lookup.

## Known Runtime Failure Modes

### Observed Child-Surface Modal Freeze Incident (2026-09-21)

- Presenting a child surface with `NSApp.runModal` froze the whole React host: the provider wizard's window painted nothing but its title bar, and the settings window behind it stopped committing (a deep link that should have switched its pane never did) for as long as the modal session was up.
- Measured cause: `NSApp.runModal` runs the main run loop in its modal mode alone. The React host's main-thread work lands on the main queue, and `RCTDisplayLink` and `RCTTiming` post their frame and timer work to the default run-loop mode; during the session a main-queue block that resolves an IPC promise never ran, and a JS `setInterval` never fired (a temporary file trace in `CoreIPCModule` plus a one-second JS probe proved both). A native modal-mode timer heartbeat that hands the default mode a slice on every pass fired at 100 Hz and did not restore either, and `sample` of the frozen app showed the main thread inside `-[NSApplication _doModalLoop:peek:]` with an idle JavaScript thread.
- Fix: the lock is a view, not a session. Every child surface opens its own movable titled window attached above the window it was opened from (`presentChildPanel(_:in:prepare:)`), and that parent receives `NativeChildPanelShield` — every mouse event swallowed, the first responder held, its window buttons disabled — until `endChildPanel` releases it. The child keeps a real window, the parent answers no click or key, and the app keeps rendering; the model chooser's selection now travels through its completion instead of a modal response.
- Verified with `tests/test_rn_native_acceptance.py` together with the driven installed app: the wizard opened as its own window with title bar and traffic lights, rendered its steps, changed the parent's pane from a deep link while it was up, closed through its React 关闭 button, and left the parent's window buttons enabled again.

### Observed Group-Manager Open Latency Incident (2026-09-21)

- 分组管理 opened only after the station round trip its aligned draft needs: `openGroupManager` awaited `resources.refresh`, `api_key.align_auto_grouping`, and an account re-read before it called `native.showGroupManager`, so the provider window showed nothing at all for as long as the station took to answer.
- Fix: the sheet opens at once on the account facts the provider window already holds, and the load lands in place. `showGroupManager` takes `loading`, the sheet shows the rows it opened on behind the busy wheel beside 密钥, and `updateGroupManager` replaces them with the aligned draft; the rows stay read-only until that update, so no staged edit can be lost to the load.
- The staged edits are still reconciled against the loaded account (the request awaits the same load before applying a result), an update that lands after Close changes nothing, and a station that cannot be refreshed or aligned keeps the keys it last reported.
- A host without the in-place update keeps the pre-load ordering: the WinUI sheet has no update surface, so its sheet opens only on data that is already loaded instead of showing a wheel it cannot resolve.
- State the wait where its rows are, with the app's own wheel. The sheet turns `AppKitBusySpinner`'s frames beside 密钥 — the same pre-rendered frames `AppKitControlViews.mm` draws as a busy button's leading image, read there through the generated Swift header the way `LiteLLMPersistentScroller` is — and keeps the words (`relay.groupManagerLoading`) as the wheel's tooltip and accessibility label. This is the one animation the native leaf may run: the wheel swaps images instead of animating a view, and the relay sign-in surface still refuses `NSProgressIndicator` and any `startAnimation`.
- Verified with `tests/test_rn_ui_parity.py` (the request/update split, the wheel beside 密钥, the snapshot field set the native side accepts), `tests/test_rn_native_acceptance.py` (the button and the sheet read one wheel) together with a driven installed app: the sheet root appeared in the same press that opened it, showed the wheel beside 密钥 with 保存并关闭 disabled, then took the loaded draft.

### Observed Embedded Sign-In Detection Incident (2026-09-20)

- On `tken.shop` the sign-in sheet never detected a completed login (`等待完成登录...` stayed on screen with the console visible behind it), and the station's own 系统公告 dialog covered the form so the account fields had to be scrolled into view.
- Cause: both relay families sign in inside a single-page app. The station keeps its session in local storage, the password form posts through XHR, and the console route change is client-side, so `didFinish` never fires again and the automatic check that ran at page load was the only one that ever ran. The station's announcement dialog is a fixed overlay over the sign-in form, and the measured form interval was taken while that overlay still occupied the viewport, so the surface never showed the first field through the submit button.
- Fix: `relayLoginSurfaceScript` hides the blocking overlay (a persistent "close for today" action is preferred, then an explicit dismissal, then a bare close affordance; a layer that survives two dismissals is hidden outright) and reports client-side navigation through the `litellmRelayPage` message handler; `scheduleLoginWatch` polls `loginStateScript` while the surface is open and starts one server-side verification per new credential fingerprint (a form that disappears and a token that appears both count), `recoverStalledCheck` drops a verification that neither committed nor finished after 30 seconds, and the New API probe sends `New-Api-User` from the page's own session record. The same page-geometry probe now measures the modal sheet as well as the embedded step, so both show the first field through the submit button without scrolling.
- Keep the JS carried by a Swift multi-line string free of backslash escapes: Swift interprets them first, and a `\t` inside a character class silently broke the whole dismissal script once. `tests/test_rn_native_acceptance.py` fails when one reappears.
- Verified live on `www.tken.shop` (announcement dismissed, form visible, no scrolling) together with the focused relay, hook, and native contract suites.

### Observed Self-Identifying User-Agent Exposure Incident (2026-09-20)

- The app told every remote party what it was: `Young-Router-Core/1` on each relay dashboard call (keys, groups, profile, resources, login), `Young Router/1 CFNetwork/3860.600.21 Darwin/25.5.0` on both macOS `URLSession` relay probes and `Young-Router/1` on the Windows `WinHttpOpen` probe, `Young-Router-Usage/1` on usage-log reads, `Young-Router-Codex-Settings/1`, `Young-Router model-context updater`, `Young-Router-dsh-vision-router/1.7.6`, `Young Router WebDAV Sync`, and the staged `pi-web-access` worker additionally sent `pi-web-access` (and a crawler-style `Mozilla/5.0 (compatible; pi-web-access/1.0; …)`). The data plane also forwarded our own User-Agent upstream whenever one of our components was its client.
- Impact: a relay could identify the router, and on a station that binds a browser session to its IP and User-Agent (`flux-code`, sub2api session binding) the mismatched probe/Core fingerprint made the session unusable, so a fresh sign-in died immediately.
- Fix: `young_router/browser_identity.py` owns one browser identity per platform. Every request the app makes on its own behalf presents it; the native hosts pin the same literal (`RelayBrowserIdentity` on macOS, `kRelayBrowserUserAgent` on Windows) and reuse it for the sign-in webview, the session proof, and the Windows probe, so a signed-in account keeps one fingerprint. The data plane forwards a client's own User-Agent byte-for-byte, replaces an incoming User-Agent that names this app, and supplies the browser identity when a request carries none; the `pi-web-access` staging step rewrites that package's self-naming literals and fails the build when upstream renames or drops them.
- Verified with `tests/test_browser_identity.py` (native/Python literal parity, shipped-source scan, data-plane steps, staging rewrite) together with the focused hook, relay, WebDAV, codex-config, usage-log, IPC, and provider suites.

### Observed Relay-Login Key-Gating Incident (2026-09-20)

- A sub2api station whose browser session check failed (`flux-code`, account read `signed_out` with no cached keys) had its locally known API keys treated as loading-failures: the station's key list was empty, `分组管理` was disabled by the login state, and the pane asked for a new sign-in before resources would load.
- Cause: `set_login_status` recorded a *session* outcome as a *resource* outcome (`resource_status=unavailable`, `resource_error=unavailable`, and in older builds `resources=[]`/`groups=[]`), `refresh_resources` refused every read while `login_status != signed_in`, the dashboard header resolver used only the in-memory session (so a Core restart dropped the explicitly remembered one), `trusted_secret_value` refused the native plaintext lease for a locally known key, `prepare_apply` demanded a fresh sign-in for journaled station work Core could still authenticate, and the account pane's key manager plus its mount refresh were both gated on the session check.
- Fix: the login status is an observation only. `set_login_status` records `login_status`/`last_updated_at` and never touches the key list or its resource state; `_headers` resolves the in-memory session first and then an explicitly remembered one (promoting it into memory), so every station read and write keeps working after a restart or a failed check; `refresh_resources`, `trusted_secret_value`, and `prepare_apply` (via `_has_session_credentials`) decide on usable credentials instead of the last session check. The account pane keeps 分组管理 enabled for any account and runs its quiet key-list refresh after a failed session restore. Only a real resource read may replace, empty, or downgrade the verified list.
- Verified with `tests/test_core_relay_accounts.py` (`test_core_keeps_cached_relay_keys_when_a_session_check_fails`, `test_local_relay_keys_stay_loadable_and_refreshable_while_signed_out`) together with the focused relay, IPC, provider, WebDAV, and React Native contract suites.

### Observed Aliased-Gemini Reasoning Rejection Incident (2026-09-19)

- A newly added `novai` route (`gemini-3.8-flash` → upstream `openai/[次]gemini-3.8-flash`) answered the router's provider probe but every Cherry Studio request failed with HTTP 400 `model "[次]gemini-3.8-flash" does not have a known Gemini thinking configuration`; the probe sends no reasoning fields, and Cherry Studio's model settings send `reasoning_effort` on every turn.
- The relay's OpenAI-chat converter maps client reasoning parameters through its own per-model thinking table before converting the completion, so an alias it cannot map is refused with a deterministic request error for every reasoning value, including `none`. The model itself still reasons: the same alias with no reasoning fields returns a normal completion with default thinking, and its native Google thinking configuration (`extra_body.google.thinking_config.thinking_level`) passes through and is honored (`minimal`/`low`/`medium`/`high` scale the reasoning tokens; `xhigh`/`max` are clamped down by the relay and `none` is refused).
- The implemented fix treats a deterministic thinking-configuration rejection on one deployment as route evidence: `_record_reasoning_parameters_compat` remembers the compatible wire shape in the shared `deployment-cooldowns.json` state (`YOUNG_ROUTER_REASONING_COMPAT_TTL_SECONDS`, default 1800). A Gemini-family upstream is replayed with the client's level translated into the native Google thinking configuration (`google_thinking_level`), which preserves the requested level; any other route is replayed without the reasoning fields (`strip`) and keeps its provider-default thinking. `_call_deployment_with_reasoning_parameters_compat` owns the ordered replays, and `_with_model_reasoning_parameter_support` applies the remembered shape in the pre-call hook before later upstream calls. The native shape nests the Google namespace one level inside litellm's own `extra_body` kwarg (`extra_body.extra_body.google.thinking_config.thinking_level`): the relay merges the literal `extra_body` body field itself, while litellm flattens its kwarg into top-level body fields, and a top-level `google` key is ignored upstream. Verify any future shape against the real relay (an invalid `thinking_level` must produce the upstream rejection) instead of assuming the body reaches the model.
- Keep the classifier narrow: it requires an explicit thinking/reasoning-configuration rejection phrase, so an ordinary request/format 400 or a content-policy error keeps the standard terminal error path and never populates the memory. The memory is per deployment, each request replays at most once per shape, and an expired entry re-probes the route with the client's reasoning request.
- Verified against the real upstream on a spare port (chat and Responses surfaces, streaming and non-streaming: the first request replays with the native shape, later requests translate before the call, and an upstream that refuses the native shape falls back to stripping) together with focused `tests/test_hooks_reasoning.py` and `tests/test_hooks_patches.py` regressions.

### Observed Log-View Refresh Energy Incident (2026-09-19)

- The macOS Battery panel listed Young Router under “使用大量能耗”. With the Logs window open on 请求 the Core burned 2.01 s of CPU per 60 s (single-second peaks of 0.61 s, `top` POWER 35.9 — momentarily above WindowServer) and the app 0.62 s; with that window closed and the same log-append count the Core used 0.08 s and the app 0.02 s. The proxy workers (16) keep their unchanged share.
- Every append re-ran the full request projection: `_records("requests")` re-read the bounded log, re-parsed each line, re-projected every row, and re-parsed the staged YAML to resolve configured public model names — 289 ms per refresh, of which 92 ms was `_configured_deployments` alone.
- Fix: `_configured_deployments` is parsed once per configuration revision (path + device/inode/mtime/size signature) and shared read-only, and the request tab keeps its projected tail per source offset, so an append parses only the new lines and a refresh costs ~5 ms while returning a byte-identical window.
- The tail may resume only at a line boundary and must rebuild on a new inode, an in-place shrink, a larger view limit, a configuration revision, or any view action; it must never diverge from a cold read. `tests/test_core_logs.py` covers reuse, partial-line completion, rotation/truncation, view limits, filters, and configuration revisions, and compares the incremental window against a fresh domain.
- Reading shared proxy state must not rewrite it: `_locked_json_state_update` now replaces the file only when the callback changed the document, because the cooldown and protocol-fallback filters run several times per attempt and used to rewrite an unchanged file (the cooldown file churned ~13 times a minute while idle).
- Keep the log poll responsive for the user: refresh cost is reduced by parsing less, never by polling less often, delaying a view, or dropping rows.

### Observed Login-Start Proxy Failure Incident (2026-09-19)

- After a login-time launch the proxy died while uvicorn spawned its workers (`forkserver` fd handshake: `RuntimeError: did not receive acknowledgement of fd`) under the boot load, and Core's single launch start had already been spent: the General pane showed 已停止 with no way to start it from the window (the lifecycle items live only in the status menu), so the user had to relaunch the app.
- Fix: the launch start retries on a bounded backoff (`SERVICE_STARTUP_RETRY_DELAYS_MS = [0, 5s, 20s, 60s]`, reset once the service runs, cancelled by an explicit Stop), and the General pane's 服务 row keeps one recovery control — 启动服务 when stopped, 重启服务 when unhealthy — reporting its result in the pane's permanent status strip.
- A launch-time start that fails must stay recoverable from the window itself; never leave a stopped service with no control outside the status menu.

### Observed Router-Path Exposure Incident (2026-09-18)

- Advertised durable copies lived in `<runtime root>/image-cache` (later `<user data>/ImageAttachments`), so the client model learned the router's storage, read it (`sips … <user data>/.young-router/image-cache/<digest>.jpg`), wrote derived crops into a router-created folder, and lost those crops when `_prune_replay_image_cache` deleted them.
- Fix: a copy lives next to the file it was made from, in that file's own directory, because the model derives every crop path from the path it reads; a router-owned source (or one with no usable directory) falls back to OS temporary storage, and `YOUNG_ROUTER_IMAGE_CACHE_DIR` still overrides both. The former `ImageAttachments` and `<runtime root>/image-cache` directories are treated as router storage, so no reference points there again.
- Fix: `_with_neutral_attachment_paths` rewrites every router-owned image path token in a replayed tool call, tool output, or message — quoted, backticked, or bare — to its copy (bytes copied first, digest-named `<digest>.<source-stem><ext>`), because the model reads its own history back and otherwise keeps working inside the router's storage. Non-image router files are never copied into a model-visible place; a trailing glob character skips the token; a client image path whose file the client deleted is restored at that exact path from the bytes the client still resends, so a replayed re-open stops failing with "no such file".
- Fix: pruning only considers this cache's own digest-named copies (`^[0-9a-f]{32}\.(jpg|png|webp|gif|bmp|tiff)$`); model-derived crops and user files in that directory are never deleted.
- Every path handed to the client model is user-visible in the transcript, so keep it next to the file it belongs to, neutral, writable, and free of spaces: never advertise a path inside the router's own storage, never rewrite a path the router cannot back with an existing file, and never let cache maintenance delete files the router did not create (pruning now only ever runs on an explicitly configured cache directory).

### Observed Unbounded Original-Resolution Replay Incident (2026-09-18)

- Codex thread `01a09b90-3ce8-76d2-88af-27e676b7e9dc` re-opened its own crops with `view_image(detail: "original")`; every turn forwarded 45.2 MB (recent originals kept at full bytes in the frozen prefix, originals exempt from the suffix budget) out of the 147.9 MB the client sent.
- `api.sisct2.xyz` rejected that body with HTTP 413 in ~2.6 s; each rejection cooled its route down, the pool emptied, and the request replayed the identical bytes in the shared route-recovery poll for hours while the client waited.
- Fix: an explicit original-resolution output replays as the shared preview plus its local path in the frozen prefix, and as the single-image representation (≤900 KB, max edge 2200) in the suffix. The incident replay forwards 2.9 MB with every image still re-openable.
- Fix: fresh (mutable-suffix) images are bounded by bytes, never by the shared preview edge. Cropping a region at several thousand pixels is how the model reads handwriting, and replaying that crop at the shared 1400 px edge threw the zoom away, so the model cropped the same region over and over; fresh images now keep up to the 2200 px single-image edge, a single fresh image gets the single-image byte target, and history images still replay as their deterministic 1400 px previews.
- Fix: HTTP 413 without the gateway capacity marker is a request error — remembered per request, no route cooldown, still one peer-route advance, never entering or continuing the recovery poll, and returned to the client with its own status and an oversized-body message. A structured-compaction capacity rejection keeps its failover treatment.
- Keep new oversized images inside the inline-image budget; never let a preservation rule become an unbounded inline history.

### Observed Signed-Prefix Image Path-Rewrite Incident (2026-09-17)

- Codex thread `01a09b90-3ce8-76d2-88af-27e676b7e9dc` was asked to total the daily drainage volumes of four pasted photos of handwritten flow sheets. - `YOUNG_ROUTER_PREFIX_IMAGE_RECENT_COUNT=0` previously resolved to "keep every output inline" because `candidate_indices[-0:]` is the whole list; zero now means every aged output converts, as its help text always claimed.
- Verified with the focused `tests/test_hooks_responses_request_prep.py` prefix-image regressions (a durable client path is reused, a temporary original survives its cleanup through the copy, an unwritable cache keeps the inline preview, and zero recent count converts every aged output) together with the hook, image-routing, and trace-logging modules.

## Hosted Computer-Use Requests

- The router runs no computer-use executor of its own and exposes no facade settings. A hosted Responses `computer` tool is served only by an upstream that supports it natively; every route here is a relay, so the honest outcome is the upstream's own answer or an explicit unavailability message.
- Never bridge a request that declares a hosted `computer` tool into a chat request unless the client also brings its own computer or browser tools (`_request_hosted_computer_blocks_chat_bridge`): the bridge drops the hosted declaration and would answer as if computer use had never been requested.
- Client-side computer use (Codex Desktop's `mcp__cua_repl`/`node_repl` namespace tools driving `Codex Computer Use.app`) passes through the ordinary client-tool path and needs nothing from the router.
- Codex declares those namespaces inside leading `additional_tools` input items, so every "does the client bring computer use" decision must inspect `additional_tools` as well as top-level `tools` and `tool_search_output` items (`tools._request_has_browser_computer_client_tool`); missing that made a chat-only route refuse the very client that brought its own executor.
- When a route's Responses endpoint does not exist, the bridged chat request keeps the client's computer use: namespace tools are flattened to functions carrying `x-young-router-responses-namespace` and their calls come back as `function_call` items with the `namespace` restored from the declaration or the bridged tool array. A hosted `computer` declaration with no client-side computer use is answered with `_HOSTED_COMPUTER_UNSUPPORTED_MESSAGE` before any upstream attempt rather than forwarding an invalid hosted tool to a chat endpoint.
- Verified end to end on a spare-port proxy against a fake chat-only upstream with a Codex-shaped turn (namespace in `additional_tools`): non-stream, streaming, and a second turn carrying `function_call`/`function_call_output` all restore `namespace: mcp__cua_repl`; the same turn without client-side computer use answers explicitly and makes no upstream call. Regressions live in `tests/test_hooks_computer_use_bridge.py`.

## Codex Task-ID Incident Triage

- Treat a supplied Codex task/thread ID as the primary lookup key. Do not begin with repository scans, source review, or broad log searches.
- Use this three-hop first pass, in order: (1) `read_thread` with only the newest 1-2 turns, (2) the exact rollout `task_complete` event, and (3) LiteLLM records for the same task ID and a narrow time window around that event. The first pass should return the parent status, latest-turn status/error, final assistant message, active child tasks, exact proxy request IDs, and upstream statuses.
- Prefer Codex task tools over filesystem inspection. If raw evidence is required, resolve the rollout path by exact task ID from the read-only Codex state database; never scan all of `~/.codex/sessions` or dump an entire rollout file.
- Query logs structurally and narrowly: filter by exact task ID, request ID, event name, and timestamp; print only timestamp, event, request ID, provider/deployment, status, and sanitized exception. Do not use unbounded `rg -C`, full log tails, or outputs containing request bodies, prompts, credentials, or API keys.
- Keep parent thread status, latest parent turn status, and child-task status separate. A child continuing after a parent transport failure is expected; a stale parent `systemError` with a completed latest turn is a task-state inconsistency, not evidence of a new project failure.
- Read source only after the exact error text or trace event identifies the owning branch. Stop investigating once the causal chain is closed, for example: task error -> proxy event -> upstream request statuses. Then make only the smallest requested fix and run its focused regression test.

- Provider/station binding contracts (both layers, keep together): `provider.select_relay_station` is idempotent — re-binding the same station is a no-op, a binding that changes only hidden source metadata (same name, same-site URL) is cosmetic and must leave the draft clean so no discard-confirm dialog appears, and a same-site URL keeps its existing `/v1` spelling (station origins omit `/v1`). The providers workspace auto-binds custom providers whose base URL matches a station by exact host (`flux-code.cc` ≠ `www.flux-code.cc`), skipping name collisions, and `provider_select_relay_station` is in the revision-retryable action list.
- Codex catalog restarts: endpoint-backed repairs require two consecutive fresh observations (0.5s probe interval) before rewriting `young-router-model-catalog.json` or queuing a restart prompt; explicit enable/disable stays immediate. The post-provider-apply refresh uses the same stable gate — do not restore single-observation restarts there.
- A managed catalog pointer must never be left dangling: Codex rejects its **entire** configuration (`failed to load configuration: No such file or directory (os error 2)`) while `model_catalog_json` names a missing file, so every conversation fails to resume until the pointer is fixed. A missing managed catalog is therefore rebuilt from a fresh endpoint observation even when the file (not just its content) is gone, a pre-rebrand `litellm-menu-model-catalog.json` pointer counts as enabled and is migrated to the current name (file first, then the key), and a dangling pointer observed with a failed endpoint probe is dropped (restart reason `catalog_missing`) instead of leaving the client unloadable. Foreign `model_catalog_json` paths stay untouched. Repairs ride the existing snapshot paths (settings/page disk poll, Core/app start, menu open, apply) — Core deliberately has no background catalog watcher, so a deletion made with every window closed is repaired on the next poll (~3s after a settings window is opened), never silently.
- The working tree is shared: other sessions or the user may have uncommitted edits in flight (check `git status` and `git stash list` before starting; a `wip:` stash may exist). Never revert or overwrite unrelated modifications; the full test suite also contains pre-existing environment failures — attribute a full-suite failure to your change only after the failing test touches a file you modified and it reproduces in isolation.
- Focused test commands must run from the repo root: keep the `cd <repo root> &&` prefix or set the working directory explicitly. An unexpected `No module named 'tests'` (or any import error) on a previously passing command means the working directory was lost — fix the command once and rerun. Do not pipe failing output through `| tail`; tail hides the traceback head where import/cwd errors live — write full output to a temp file and grep it, or use `head -30`.
- Never re-run a command that already failed with the same output. Two identical failures in a row is a hard stop: change something material (cwd, flags, output capture) or stop and diagnose from the full error. Retrying an unchanged failing command is not diagnosis and has burned 10+ minutes of a background session.
- To take over a looping background session instead of watching it burn: identify it by JSONL growth (`stat` the file under `~/.pi/agent/sessions/<workspace>/` twice a few seconds apart), stop it from the pi-web UI (sidebar → open the thread → composer 停止 button — the host process is shared, never kill the `pi-web` process), and extract the user's outstanding requests from the same JSONL (`role == "user"` messages) before resuming the work in the current session.
- Gate every native build with the fast checks first: `pnpm run typecheck` inside `rn/` (seconds), then `tests.test_rn_ui_parity`, `tests.test_rn_native_acceptance`, and the focused Core module for the touched domain. A green gate avoids burning multi-minute rebuild cycles on TypeScript or contract breakage that those checks catch instantly.
- Adding a `NativeTable` prop touches five files in one change: `ui/NativeControls.tsx` (props type + destructure + nativeProps), `ui/macos/NativeTableNativeComponent.ts` and `ui/windows/NativeTableNativeComponent.ts` (codegen specs), `AppKitControlViews.mm` (`updateProps` equality + render path), and `WinUIControls.cpp` (`ApplyProps` equality + render path). Missing the equality check makes the prop apply once and then never update; missing a spec or a platform render silently no-ops on that host.
- New native bridge methods with scalar parameters are positional at the native boundary: the UI-facing `NativeLeafAdapter` may accept an options object, but `platformEntry.ts` must spread it into positional args when calling `leaf.*`, and `Bridge.m`/`Module.swift` declare them positionally. Passing an options object to a positional TurboModule method crashes at runtime with `NSInvalidArgumentException ... unrecognized selector sent to instance 'length'` while typecheck stays green — exercise the real flow once before declaring done.
- Fixed `labelWidth` values narrower than the rendered CJK label wrap mid-word (five characters ≈ 70 px at `UI_FONT_SIZE`; both label and value widths shrink when the inspector column is tight). For inline labels prefer adaptive width (`width: undefined` + `numberOfLines={1}`); reserve fixed widths for short known labels such as 密钥名/密钥值.
- System Events does not enumerate sheets as windows (`count windows` misses them) and its `window 1` is not reliably the window you expect; the harness `find_roots` reports sheets as separate `sheet` roots and marks the parent with `sheets=1`. Verify sheets and click their controls through the harness only.
- Harness state goes stale across `build-and-install`, a deep-link reopen, or any sheet transition; re-run `find_roots` and re-observe before every `act_ui` batch instead of reusing refs or stateIds across those events.
- Diagnose Codex tool-surface questions from recorded data, not code reading: `~/.young-router/recent-requests.jsonl` (per-request `tool_names`/route/status, including the bridge's internal sub-requests), `~/.codex/sessions/**/rollout-*.jsonl` (calls the client actually made), and `server.log` `litellm_route_trace` events (full upstream error text). The call shape identifies the surface: JSON `function_call` = direct, a `custom_tool_call` wrapping JS = code-mode.
- `codex exec` is not Desktop-equivalent: the Desktop app additionally attaches app-only namespaces (`mcp__codex_app`, …), so CLI-green does not prove Desktop-green; diff the per-request tool lists when a failure is Desktop-only.
- Catalog route-owned fields are normalized in `_catalog_model`: non-exact-match routes get `shell_type: "shell_command"` + `tool_mode: "direct"`; exact native slugs keep their surface; `supports_search_tool` stays false off-GPT. Verify every catalog enum against the installed Codex binary (`codex debug models --bundled` or a `strings` token dump) before writing — one unknown value rejects the whole catalog; `apply_patch_tool_type` accepts only `freeform` (the JSON variant was removed upstream). Never hand-edit `young-router-model-catalog.json`; regenerate via `write_catalog` with the same `ModelContextRegistry` construction as `core/domains/codex.py`, or Apply writes the stale payload back.
- Client compacted tool schemas (`$defs.__schemaN` with `$ref` beside a sibling `type`) get 400-rejected by strict relay-side validators and surface as a stream disconnect. Schema repairs belong in `_responses_chat_bridge_tool_schema` — the single choke point every bridged parameter schema passes through — with a regression test quoting the upstream rejection text; Desktop turns always carry namespaces, so they are always bridged.
- A/B a proxy fix against the real upstream on a spare port (repo code + bundled Python + the app's runtime config), then stop the process by port. Replayed requests must carry a Codex client marker header (`Originator: codex_desktop`); an unidentified client goes native-passthrough and silently skips the bridge paths under test.
- The mandatory PyPI sync fails intermittently through the local proxy (`urlopen error [SSL: UNEXPECTED_EOF_WHILE_READING]`). Retry the same deploy in a bounded loop until the log shows `Updated LiteLLM lock`; never bypass the sync.
- AppKit `NSControl.target` and `NSTableView.dataSource/delegate` are weak: a sheet that still paints rows but ignores every button means its controller was deallocated. Retain it on the leaf and, when a control looks dead, trace the action entry points to a temp file before rewriting logic.
- `act_ui` presses can change a checkbox's drawn state without sending its AppKit action. Judge a toggle by the enable/disable flips in the response's change list, not by the checkbox pixels; select list rows with `press` on the table ref followed by arrow keys.
- React `Pressable` rows are not AX-activatable in this Fabric macOS build (the Fabric view has no `accessibilityPerformPress`), so `act_ui press` on them is a silent no-op and VoiceOver cannot activate them either. Rows that must be clickable, keyboard-navigable, and harness-verifiable should be a `NativeTable` selection or another native control; the runtime pane's category table of contents is the reference implementation.
- The settings window owns one sidebar material: `AppDelegate.mm` gives it `.fullSizeContentView`, a transparent hidden title bar, a non-opaque clear window, and an `NSVisualEffectView` (sidebar, behind-window) content view. `RCTSurfaceHostingView` defaults to opaque white on macOS and must be cleared, otherwise it hides the material; source-list tables must stay transparent (no per-table backdrop) or the table area double-blends and reads darker than the surrounding sidebar. React then leaves the sidebar and pane header transparent and paints only the detail body (`textBackground`), with `SETTINGS_TITLEBAR_INSET` pushing sidebar content below the traffic lights.
- React dialogs rendered inside the provider inspector (`providerInspector`, 300 pt) are clipped — `RelayDialogLayer` is absolutely positioned inside its parent. Route-level dialogs belong to the route surface; the relay group manager stays a native provider-window sheet.
- Two Swift type errors cost a build each: option sets take `[]` (`table.gridStyleMask = []`, not `.gridNone`), and `accessibilityLabel` is a method (`setAccessibilityLabel(_:)`). `swiftc -parse` catches syntax only.
- Windows native code cannot be compiled locally, so declare C++ helper lambdas after the locals they capture and keep the WinUI structure a literal mirror of the macOS one; scoping mistakes only surface on a Windows host.
- Native editors follow the app's master-detail pattern: list with ＋/－ in the pane header, detail for the selection, and 关闭/应用 in the footer. Staged edits return on Apply; Close discards them.

## Public Repository Hygiene

- Do not commit runtime directories, virtual environments, package installs, generated app bundles, logs, screenshots containing real data, local traces, or WebDAV settings.
- Before every commit or push, inspect untracked files and the staged diff for credentials, private endpoints, provider/model names, request or task IDs, local paths, and copied configuration. Replace real values with neutral fixtures.
- Re-run the sensitive-data check against the staged diff before pushing. Tests passing does not replace this review.
- Use the intended public or noreply Git identity for public remotes.
